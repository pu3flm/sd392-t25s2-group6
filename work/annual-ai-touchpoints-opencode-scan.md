## Coverage and access limits

The database was opened read-only. The scan inspected `session` metadata (identifier, parent relationship, title, directory, and timestamps) and text parts joined through `message` and `part` only when the message role was `user`. No assistant-response content was used. Obvious generated background notices, repeated forks, delegated child sessions, and unrelated personal or routine system interactions were excluded; repetitive interactions were consolidated into representative touchpoints.

The database contains 937 sessions dated from 2026-03-04 through 2026-07-24, including 541 sessions with a recorded parent and 396 without one. No session has a non-null archived timestamp. Some automation-generated notices are stored with the `user` role, so role metadata alone cannot perfectly distinguish typed prompts from injected control messages; obvious instances were omitted. Dates are approximate local dates derived from stored timestamps using `America/Sao_Paulo` (UTC−03:00). This is a memory aid based on local metadata and visible user prompts, not a completeness or outcome audit.
